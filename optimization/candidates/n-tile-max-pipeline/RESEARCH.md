# N-tile early max pipeline

Final archival note (2026-10-17): remains unsubmitted and unpromoted. The

Parent: exact official 16.89 FIFO (`6ad335a8193e507d8e985b8b`). Independent
of concurrent MIX 1:2 and FIFO+UB8192 work. Only extends the FIFO dispatch to
4096<N<=16384, M>=1024, with per-N-tile ready/consumed handshakes. AIV updates
16 row maxima as Cube produces each tile; after row completion, original
quantization reloads the complete row. Retains two row slots but serializes
row reuse in the new path. Narrow FIFO and other fallback paths unchanged.

The initial immediate acknowledgement serialized producer and max scan. The
current revision instead permits two tiles outstanding, using ready events
4/5, consumed events 6/7, row-complete 8 and row-consumed 9. Producer waits for
the old tile acknowledgement before reusing its event lane, then drains both
lanes before row completion. Full row slots retain C; only event lanes recycle.
Expected risk: event overhead per 256-column tile may outweigh any benefits.
Also known: when bypassing FindRowMax, two-tile activation caching cannot be
used. Default QUANT_CACHE_TWO_TILES must remain disabled. Wide-N quantization
always reloads activation; no reliance on fpBuffer retaining a complete row.

Targeted tails and event reuse have passed the limited tests below, but broad
cross-core visibility, MTE acknowledgement ordering, extrema and K-chunk
coverage remain unproven. No root changes or promotion absent a higher
exact-ID official score.

- Both default and probe benchmark builds pass CANN 9.1/dav-2201.
- Strict INT32 CAModel under `source env.sh Ascend910B1`: 17x4097x33,
  17x8201x33, 65x4097x33 pass with probe minimum M=17 and normal core cap.
  33x16385x33 passes the fallback path, not early-max protocol. All have zero
  INT8 mismatch and exact yScale (rtol/atol 1e-4).
- Single-core probe 33x4097x33 explicitly forces three row jobs, both event
  lanes, row tail and slot reuse: zero mismatch, exact yScale. See
  `results/strict-one-core-reuse-v1/`. The probe binary was rebuilt with a
  one-core cap only after the four preceding tests; their recorded fingerprints
  retain the original binary hash. They must not be reinterpreted as one-core.

  logs retained in `results/strict-production-20261017/`. It is neither a
  correctness pass nor a proven deadlock. Only this runner's process group was
  terminated. Initial attempt with vendor set_env alone failed aclInit=500000;
  using the repository's simulator env enabled actual execution.
- No paired performance measurement or formal submission yet. No speedup claim.
  Current verified best has independently advanced to dual-AIV 19.45, source
  `evidence/formal/dual-aiv-fixed-6ad33b78/`; root untouched by this candidate.
